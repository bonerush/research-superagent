# 010 接入与使用

这份讲怎么把研究域接到你自己的机器与日常流程里。研究域与新工单域共用同一个插件；插件本身的安装见 `SETUP.md`。

## 一、机器

研究域不硬编码任何云厂商，它从环境变量读四个端点和两个标识：

| 变量 | 作用 |
| --- | --- |
| `RESEARCH_MACHINE_TOKEN` | 调用控制面 API 的凭据；只出现在请求头里，永不落盘、不进错误信息 |
| `RESEARCH_MACHINE_INSTANCE` | 要控制的那台实例的 id |
| `RESEARCH_MACHINE_STATUS_URL` | 查状态的端点 |
| `RESEARCH_MACHINE_ON_URL` | 开机端点 |
| `RESEARCH_MACHINE_OFF_URL` | 关机端点 |
| `RESEARCH_MACHINE_BALANCE_URL` | 查余额端点 |
| `RESEARCH_NOTIFY_COMMAND` | 可选：通知命令。待挑提案、报告就绪时，插件把一行消息写到它的标准输入 |

四个端点由你按厂商文档填，插件只负责发 `POST`、带 `authorization` 头与 `{ instance_id }` 体，并按状态码判成败。五个变量缺一个，机器动作就会明确报「no machine is configured」，不会假装可用。

通知命令由你提供，插件不发明厂商语法——你写一个脚本（比如调飞书机器人），消息从 stdin 进来。没设这个变量就没有通知，面板是唯一界面，而不是一个静默的空动作。

配置好之后：

- supervisor 每分钟跑一轮，读账本里的活动（未结束的 run 视为在跑，开机时间作为空闲窗口的兜底），**无活动满一小时就关机**；关成功才记账。
- 开机、关机、查状态、查余额都可以从主会话的 `research` 工具发起（`action: "machine"`）。

## 二、数据放在哪

都在插件的状态目录（`stateDir`）里：

| 文件 | 内容 |
| --- | --- |
| `research.sqlite` | 问题、批次、契约、协议、尝试、run、决定、证据、报告、机器状态 |
| `research-agenda.md` | 议程：收成果与判死写下的结论，一行条目的 Markdown |

它与工单域的 `orchestrator.sqlite` 并排、互不影响。备份或迁移时两套一起拿。

## 三、一次完整的研究循环

全部发生在主会话里，用自然语言说就行；下面括号里是它背后调用的动作。

1. **给方向**：「这个方向我想看 X，要求是架构上要有新东西。」（agent 开始查文献）
2. **收提案**：「给我五个候选。」（`research` / `propose`：每份必须带三条最近先例与 delta）
3. **批判**：（批判 agent 交 `critique`；全部被否的批次不会到你这）
4. **挑一个**：「我挑第三个。」（`pick`：记一条人的决定，其余候选连理由存起来作品味信号）
5. **签契约**：「按这个签。」（`sign`：契约从被选候选派生，签完冻结，重复签被拒）
6. **跑**：实验 agent 登记协议（`protocol`）、开尝试（`attempt` open/start）、记 run（`run`）
7. **收**：跑完下结论（`attempt` conclude，证据必须是本尝试的 run），封证据（`evidence`：给一次独立重跑的 commit、数据哈希、命令与指标，判定由插件算）
8. **判**：「收」或「判死」（`decide`：收要已复现且 verdict 是 supported；判死要理由加批判意见）

收成果或判死后，结论会写进 `research-agenda.md`，下一次提案可以读它。

## 四、面板

面板的「研究」页签读 `GET research`，一屏四块：**待签契约、待挑提案、待判定尝试、报告**。已被挑走的批次、已收成果或已判死的尝试不会列出来。

页签上可以直接做两件事：**点候选编号挑提案**、**点「收」收成果**。签字要写要求、判死要给理由和反方意见，这两件事留在对话里说。面板与主会话共用同一套动作（`src/app/research-actions.ts`），所以两边记下的决定一模一样。

## 五、还没接上的

- **飞书通知**：研究事件还不会推给你，面板是唯一界面。
- **人专用路由**：`pick`/`sign`/`decide` 现在挂在主会话工具上，工具描述里要求「只在该人明确表态后调用」，但那是约定，不是强制边界。
- **议程回读**：议程会被写，也能用 `research` 的 `agenda` 动作读出来；但提案阶段还不会自动读它，agent 需要显式调一次。
