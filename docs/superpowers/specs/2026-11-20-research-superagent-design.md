# 研究代理设计（Research Superagent）

日期 2026-11-20 · 状态：待审 · 分支：doc/research-superagent-design

> 本文用中文写。核心术语（判死、点头、议程、验收契约）是对话中定下的，翻成英文会丢。定稿后另出英文版并入 `docs/00x`。

## 摘要

一个人类（领导）加一群 agent（研究组），把一条研究方向从模糊想法推进到「可复现证据 + 结论报告」。人只在三处点头：**签契约、判死、收成果**。其余全部自动。

现有仓库是一个多用户、事件驱动的 coding agent：Source 产生 Trigger，Eval 判「谁有权提这个活」，Ticket 带授权派给 Executor。研究循环的前提正好相反——请求方是 agent，唯一审批者是一个人类，工作单元要活几周而不是一个工单。所以换的是域模型，留的是基建。

## 1. 为什么做

- 研究的瓶颈不是写代码，是**判断**：这个方向新不新、值不值得做、证据够不够、该不该停。
- 这三类判断现在都要人做，而且做的时机很糟：等实验跑完了才看到方向错了。
- 所以把钱和算力花在**前置**：让它在纸上（提案、协议、判据）花更多功夫，在机器上花更少。

## 2. 目标 / 非目标 / 反目标

| | |
|---|---|
| **目标** | 一条方向从提案到报告全自动，中间不需要人盯 |
| | 每个结论可追溯到 run、机器、commit、参数 |
| | 每个尝试的机时与金额可归集到方向 |
| | 失败与走死的路径被记录并被议程吸收，不重复烧钱 |
| **非目标** | 多用户权限体系（没有外部陌生人） |
| | 自动投稿、自动联系合作者 |
| | 湿实验 |
| | 通用 coding agent |
| **反目标**（技术成功但这件事失败） | 报告很多，但人一份都不看 |
| | 把噪声当结论，或把失败包装成「还需要更多算力」 |
| | 烧光余额，而人不知道为什么 |
| | 分支树烂到没人能读出实验历史 |

## 3. 约束

AutoDL 一类租用 GPU（已核对官网计费文档）：

| 事实 | 后果 |
|---|---|
| 按开关机时间计费，关机即停；精确到秒 | 空闲一分钟都是钱 |
| 关机后数据保留一段时间 | 环境可以靠磁盘活着，不必常开 |
| 关机后 GPU 不预留，下次可能被租走 | 实验协议要声明占机时长，或接受等待 |
| 无卡模式 ¥0.1/小时（0.5 核 / 2G / 无卡） | 改代码、传数据、写结论走这一档 |
| 关机后标准输出不可见 | 日志必须自己落盘 |
| 官网余额即预算上限 | 不需要另建预算系统，只需要记账 |

其他约束：git 分支模型沿用 `dsh-obsidian-mem`；单账户、单仓库；可用模型包括同模型不同提示与不同模型。

## 4. 域模型

### 概念

| 概念 | 是什么 | 不变式 |
|---|---|---|
| **Lab** 实验室 | 仓库 + 机器池 + 环境镜像 + 数据 | 主工作区只放跨尝试复用的东西；一次尝试的产物只在该尝试的分支上 |
| **Agenda** 议程 | 长生命周期的研究方向集合，不属于任何一次尝试 | 它是唯一长期记忆；结论只能从这里被读到 |
| **Question** 问题 | 方向 / 选题 / 假设是同一个对象的不同精度 | 走到 `hypothesis` 精度时必须带 `prediction` 与 `test`（怎么算证伪） |
| **Proposal** 提案 | 一组候选方向，默认 5 个 | 没有最近先例（≥3 篇）与 delta 的提案不交付 |
| **Contract** 验收契约 | 人签一次后冻结的验收基准 | 冻结后改动等于新契约；旧尝试仍按旧契约判 |
| **Attempt** 尝试 | 一条分支 + 一份事前登记协议 + 一组 run + 一个 verdict | 一个 agent 不能既提它又判它 |
| **Run** 运行 | 一次上机：机器、镜像、commit、命令、参数、起止、金额、日志、产物 | 没有 run 的结论是意见，不是结论 |
| **Member** 成员 | agent 的身份、角色、归属 | 每个动作都记 member id |
| **Decision** 决定 | 人做的一个判断：签契约 / 判死 / 收成果 | 只有人能产生；agent 只能建议 |

Question 的精度轴：

```
direction（模糊的方向）
   └─ topic（精确到一个可讨论的问题）
        └─ hypothesis（可证伪的断言 + 预测 + 判据）
```

### 状态机

```
Question:  open ─→ testing ─→ answered | abandoned
Attempt:   opened ─→ running ─→ concluded(supported|refuted|inconclusive)
                                └→ abandoned
Run:       queued ─→ started ─→ finished | failed | killed
Machine:   off ─→ booting ─→ idle ─→ running ─→ idle ─→ off
                └─(无卡)─→ idle_nocard ─→ off
```

### 不变式（八条，写进代码而不是提示词）

1. 契约冻结后不可修改；要做新的，开新契约版本，旧尝试按旧契约判。
2. 任何结论必须指向至少一个 run；没有 run 的结论只能是 proposal。
3. 删分支之前，该尝试的结论必须已经写进议程。
4. 关机之前，日志必须已经落盘。
5. 判死只能是一条人的 Decision；agent 只能提交建议和证据。
6. 提案人与批判人不能是同一个 Member 上下文。
7. 机器空闲满 1 小时（无 job、无会话、无传输）自动关机，此规则不需要人批。
8. 单个尝试的开销超过契约里的上限时，停在 `waiting`，等人。

## 5. 循环

### 阶段一：提案（便宜，都在纸上）

```
画像 + 文献扫描
      ↓
5 份候选提案（问题 / 为什么现在 / 先例与 delta / 可行性 / 协议草稿 / 最可能失败处）
      ↓
批判 agent 预筛（保守：只杀明确不新、明确做不了的）
      ↓
人选一个 → 契约草案 → 人签 → 冻结
```

为什么一次给 5 个：人说不清自己想要什么，但认得出。挑选这个动作本身就是免费的偏好标注。

### 阶段二：执行（贵，都在机器上）

```
议程排期 → 开 attempt 分支 → 写协议（事前登记：命令、判据、预期、停止条件、占机时长）
      ↓
开机（或先开无卡模式备环境）→ 跑 → 日志落盘 → 关机
      ↓
证据归档：run 记录 + 日志 + 产物 + 金额
```

协议必须**事前登记**。没有它，「程序走完了没有」无法核查，它会永远说「还差一组消融」。

### 阶段三：收敛

```
读证据 → verdict（supported / refuted / inconclusive）
      ↓
结论写回议程（包括走死的路）
      ↓
要交结果时：clean checkout 上重跑一遍 → 证据包 + 报告 → 人验收 → 判死或继续
```

重跑这一遍是「程序走完」的硬检查，也是唯一能证明「可复现」的动作。

## 6. 机器生命周期

三档，默认停在最省那档：

| 状态 | 花费 | 干什么 |
|---|---|---|
| 关机 | 只有存储 | 默认态 |
| 无卡模式 | ¥0.1/h | 改代码、传数据、整理结果、写结论 |
| GPU 开机 | 按卡计费 | 只为跑实验 |

**双重关机**，缺一不可：

1. 第一层，脚本自带：实验命令后挂 `/usr/bin/shutdown`，跑完自动关，不依赖 agent 记得。
2. 第二层，外部兜底：监督进程每 2 秒看一次，无 job、无会话、无传输满 1 小时则关机。

第一层会在进程崩溃、服务卡住时失效，第二层接住。

已知风险：关机后 GPU 可能被租走。缓解是协议里声明占机时长；实在开不回来就换卡型或等。

## 7. 组与分工

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| 探路 | 扫文献、提候选提案 | 不开机器 |
| 实验 | 开机器、跑协议、取证据 | 不改判据 |
| 批判 | 预筛提案、找最近先例、攻击新意 | 不写提案 |
| 写作 | 把证据和结论写成报告 | 不碰实验结果 |
| 记账 | 维护议程、钉结论、清理分支 | 不参与判断 |

**批判层必须是真的。** 优先用不同模型；同一模型时退到信息隔离——它只看到提案的结论与证据，看不到提案人的推理过程。否则 agent 之间会互相点头，审稿人只会复述提案再加一句「有价值」。

**记账是多人协作的代价。** 谁在哪个 commit、哪台机器、跑了哪组参数，必须可追溯。git 分支树是账本，每次尝试结束时把结论和证据钉回议程。

## 8. 三个点头点

每一处，agent 要交的东西是固定的：

| 点头 | 它交什么 | 人要回答 |
|---|---|---|
| **签契约** | 5 份候选的对比、它推荐哪份及理由、冻结后的契约（目标 / 要求 / 判据 / 协议 / 预算上限 / 停止条件） | 签，或改一版 |
| **判死** | 程序完成度（跑了哪些、跳了哪些）、结果对照判据、反方意见（批判 agent 的反对理由） | 停，或继续 |
| **收成果** | 证据包（分支 + 配置 + 数据快照 + 日志 + 一键重跑）、报告、它自己的复现重跑结果 | 收，或打回 |

判死要带反方意见，这一条是硬的：只交「我认为该停」等于没给判断材料。

## 9. 存储与账本

一条简单的规则：**慢状态进 git，快状态进 store。**

| 慢（人会读、要版本） | 快（会变、只在操作时读） |
|---|---|
| `research/agenda.md` | run 记录、机器状态 |
| `research/contracts/<slug>.md` | 会话、任务、花费流水 |
| `research/attempts/<slug>.md` | 队列、锁、心跳 |
| `research/reports/<slug>.md` | |

理由：结论要能被人和 git 读到；操作状态变得快，不该污染 git 历史。

## 10. 与现有代码的关系

保留的是机制（跟研究无关、跟可靠性有关），换掉的是域（跟研究有关）：

| 处置 | 东西 |
|---|---|
| 保留机制 | Store 的事务与迁移、Panel 框架、Outbox 投递、Session 生命周期、Effects、崩溃恢复 |
| 重写 | 域模型、表结构、面板视图、prompts |
| 删除 | admission、授权用的 policy、跨 Source 身份映射、GitHub 监听那套 |
| 改用途 | 飞书/GitHub 只留「结果推给人」的通知通道 |

文档：`docs/002-authorization.md` 整篇删除；`001-domain.md`、`003-execution.md` 重写；`004-prompts.md` 按新角色改写。

## 11. 备选方案与选择

| 方案 | 做法 | 代价 |
|---|---|---|
| A 在旧域上叠一层 | 议程当作长寿 Thread，提案与契约当作 Input，尝试当作 Ticket | 改动最小，但多用户、事件驱动、一票一目录的假设会一直跟新功能打架 |
| **B 换域留基建（选它）** | 保留机制，重写域；删授权层 | 中等工程量，表与视图重写 |
| C 回到会话原语重写 | 写编排器，按角色起 DSH 会话，状态放文件 | 最轻，但面板、通知、崩溃恢复全要重造 |

选 B 的理由：真正错的是域模型，真正对的是基建。A 会把错的假设一路带进每个新功能；C 会把对的基建扔掉，把踩过的坑再踩一遍。

前提：**得先能删**。删不干净，B 会不知不觉退回 A。

## 13. 未决

- 系统叫什么名字（仓库名 research-superagent 与包名 dsh-superagent 不一致）。
- 报告只给用户自己看，还是也会传给合作者/导师——决定它敢不敢写坏消息。
- 同时在跑的尝试上限（建议起步 2 台 GPU）。
- 文献源：arXiv / Semantic Scholar / OpenReview，各自覆盖什么。
- AutoDL 用开放 API 还是纯 SSH + 网页（API 能开机，SSH 只能进去）。
- 余额的硬下限（建议留 ¥50 作安全垫）。
- 画像的结构（分节模板 vs 自由文本）。

## 14. 这份设计怎么算通过

1. 一个没参与过这场对话的 builder，能据此排出实施计划。
2. 三个点头点各自的交付物有明确定义，不需要再问。
3. 每条反目标都有一条对应机制，而不是一句愿望。
4. 十条不变式里，没有一条是只能靠提示词实现的。
